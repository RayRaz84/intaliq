# Two-Story CI/TPRS Reading Blueprint — Governing Rules for the Course

*Owner's document, adopted verbatim **2026-09-13 (SC-057)**. This is now the **governing standard for every reading in the line**. Where it and any earlier instrument disagree, this wins, and the earlier instrument is amended rather than argued with. The Editor's implementation notes are confined to the clearly marked appendix at the end and change nothing in the rules themselves.*

---

## 1. Core Principle

Each unit contains two substantial narrative readings. They are not simply two versions of the same story. They serve different acquisition purposes.

**Story 1 — Present-Time Story** *(the fixed slot, SC-041 → **SC-073**; applies from Unit 1 and in every unit — and the imperfect is never used as pseudo-past narration)**:** primarily present/imperfect · establishes and heavily recycles the unit's new core language · maximizes immediate comprehensibility · creates repeated exposure through a genuine problem or situation · contains meaningful dialogue so learners encounter first- and second-person forms naturally.

**Story 2 — Past-Time Story** *(the fixed slot, SC-041 → **SC-073**; applies from Unit 1 and in every unit)**:** primarily past tense in the narration · uses the same unit language in a genuinely different story · introduces or reinforces a small, explicitly controlled set of past forms · demonstrates how familiar vocabulary behaves in recounting completed events · also contains dialogue, where present-time first- and second-person forms can occur naturally.

The relationship should be: **Story 1 builds the language. Story 2 expands what learners can do with it.** Story 2 must never be merely Story 1 rewritten in the past tense.

## 2. The Acquisition Core Must Remain Stable

Both stories should heavily recycle the current unit's core structures, high-frequency language from previous units, a small set of core nouns, and already established connectors and question forms. The majority of the text should consist of language learners already understand or are actively acquiring. New support vocabulary should remain small and purposeful.

**Core language carries the story. Support language makes the story natural.**

Support language may clarify setting, motivation, one important object, a necessary action, or a meaningful payoff. It should not carry the entire plot. **If removing the support words makes the story impossible to understand, the support load is probably too high.**

## 3. Every Story Needs a Real Narrative Engine

A story cannot consist merely of: *X wants something. X goes somewhere. X sees something. X is happy.* At minimum, something must create a reason to continue.

A successful story usually contains some combination of: a want · a problem · a question · an expectation · incomplete information · a misunderstanding · a choice · a failed attempt · an unusual situation · a discovery · a reversal · a resolution. But the exact sequence should vary.

**The test:** *If the learner already understood every word, would there still be a reason to find out what happens?* If not, revise it.

## 4. Do Not Use One Story Formula Repeatedly

The course should deliberately rotate narrative structures.

| | engine |
|---|---|
| **A** | **Search / Quest** — someone wants or needs something and looks for it |
| **B** | **Mistaken Identity** — someone misunderstands who a person or object is |
| **C** | **Exchange** — two characters each have something the other needs |
| **D** | **Routine Interrupted** — a familiar routine stops working because something changes |
| **E** | **Mystery** — something is missing, changed, moved, empty, or unexplained |
| **F** | **Unexpected Visitor** — a new person or animal changes an ordinary situation |
| **G** | **Failed Attempts** — a character tries several reasonable solutions before one succeeds |
| **H** | **Choice / Dilemma** — a character has two possible options and must choose |
| **I** | **Information Gap** — one character knows something another needs to discover |
| **J** | **Misunderstanding** — characters interpret the same situation differently |
| **K** | **Favor / Help** — one character tries to help another but encounters a small obstacle |
| **L** | **Object With a History** — an object moves between people or places and becomes meaningful |
| **M** | **Promise / Expectation** — a character expects something to happen, but reality develops differently |
| **N** | **Quiet Transformation** — the external problem is small, but a relationship or social situation changes |
| **O** | **Comic Escalation** — the same situation repeats with increasingly surprising results |

**Do not use the same engine in consecutive units** unless the surface structure and resolution are substantially different.

## 5. Story Shape Must Also Vary

Do not make every story follow *problem → attempt → failure → second attempt → success*. That is only one useful shape.

**Discovery** — ordinary situation → strange detail → investigation → discovery · **Reversal** — learner assumes X → evidence suggests X → final information reveals Y · **Accumulation** — small event → another related event → pattern becomes visible → payoff · **Convergence** — two characters begin separately → their wants intersect → one solution resolves both · **Circular** — story begins with an object/action → events change its meaning → ending returns to it · **Choice** — two possibilities → information about each → decision → consequence · **Social** — new person → uncertainty → interaction → misunderstanding or connection → changed relationship · **Surprise ending** — apparently solved problem → small final detail changes how the reader interprets it.

Narrative variation should be designed intentionally.

## 6. Story 1 — Present-Tense Rules

Story 1 should make the new language highly transparent. Narration will usually rely on third-person present/imperfect forms, possession, location, wants, seeing, going, asking, giving, finding, and other previously acquired high-frequency structures. **Do not force every current target into every paragraph.** The repetition should arise naturally from the situation.

Story 1 should generally: establish the central situation quickly · give the protagonist a meaningful want or problem · make the unit's core structures necessary to understand what happens · create repeated exposure through actions or information · contain meaningful dialogue · resolve the main problem · end with a small payoff when possible.

The primary narrative tense remains present/imperfect.

## 7. Story 2 — Past-Tense Rules

Story 2 should be a new narrative, not a grammar conversion exercise. Its narration occurs mainly through past tense. The course should introduce **only a bounded number of past forms at a time**.

If learners know يَذْهَبُ · يَرَى · يَجِدُ · يُعْطِي, a unit might deliberately introduce only ذَهَبَ · رَأَى · وَجَدَ · أَعْطَى — **if these are genuinely needed.** Do not automatically teach every person of every past-tense verb. Past forms should be learned through repeated meaningful events before full paradigm analysis.

Narration can say **ذَهَبَ عُمَرُ إِلَى الْمَكْتَبَةِ** while dialogue naturally contains present forms — **قَالَتْ سَارَةُ: «مَاذَا تُرِيدُ؟» قَالَ عُمَرُ: «أُرِيدُ كِتَابًا.»** This is desirable: it allows third-person past narration, first-person dialogue and second-person dialogue inside one comprehensible text.

## 8. Dialogue Is a Required Acquisition Tool

Every substantial story should contain dialogue where the plot naturally permits it. Dialogue is not decorative. Its main linguistic purpose is to give learners repeated exposure to forms that third-person narration cannot provide naturally.

Narration tends to provide هو / هي · يريد / تريد · عنده / عندها · ذهب / ذهبت. Dialogue naturally provides أنا · أنتَ · أنتِ · عندي · عندكَ · عندكِ · أريد · تريد · تريدين. **This allows person forms to develop through communication rather than conjugation charts.**

## 9. Dialogue Must Do Story Work

Do not write dialogue only to display grammar. Weak: *— هل تريد البيتزا؟ — نعم، أريد البيتزا. — هل عندك بيتزا؟ — لا، ما عندي بيتزا.* — unless the characters genuinely need this information.

Strong dialogue asks for needed information · corrects misunderstanding · gives a clue · refuses or accepts something · reveals a want · changes the character's next action · causes a discovery · establishes a relationship · creates humor.

**Ask: if this dialogue disappeared, would anything in the story change?** If not, rewrite it.

## 10. First- and Second-Person Forms Should Emerge Through Dialogue

Do not artificially insert أَنَا أُرِيدُ… / أَنْتَ تُرِيدُ… / هِيَ تُرِيدُ… as a disguised conjugation exercise. Instead create situations where speakers genuinely need these forms. Person variation should emerge from speaker roles.

## 11. Repetition Must Be Motivated

CI/TPRS requires abundant repetition, but the learner should experience **repeated meaning** rather than **repeated sentences**.

Useful narrative reasons for repetition: several people have different information · the protagonist checks different possibilities · something happens repeatedly with a changing result · characters misunderstand one another · two people want different things · an object moves · a routine repeats · an expectation keeps failing · a clue becomes more specific · a character must ask more than one person.

**Every major repetition should answer: why does the character need to encounter this structure again?**

## 12. Variation Inside Repetition

Repetition should not mean copying the same sentence. Instead of *آدم يريد كتابًا. سارة تريد كتابًا. عمر يريد كتابًا.* use contextual variation:

> يُرِيدُ عُمَرُ كِتَابًا.
> — مَاذَا تُرِيدِينَ يَا سَارَة؟
> — أُرِيدُ الْكِتَابَ أَيْضًا.
> لٰكِنَّ لَيْلَى لَا تُرِيدُ الْكِتَابَ.

**The semantic core repeats while discourse changes.**

## 13. A Meaningful Anchor Helps Hold the Story Together

Each major story should normally have one important anchor: object · person · place · question · goal · message.

Ask *why does this particular thing matter to this character?* — not *"because it is one of this unit's vocabulary nouns."*

Not merely a picture, but a picture someone needs · not merely a book, but the book another character is looking for · not merely pizza, but the thing one character has and another lacks · not merely a chair, but the chair that signals someone now belongs. **Specificity creates narrative meaning.**

## 14. Emotional Engagement Does Not Mean Emotional Vocabulary

Stories should produce curiosity · amusement · recognition · anticipation · mild concern · satisfaction · surprise. They do not need many emotion words.

Instead of repeatedly writing هو حزين / هو سعيد, the story may **show the reason**. Emotion should emerge primarily from the situation, character behavior, dialogue, repetition, visual support and resolution. High-frequency emotional adjectives may still be recycled **when they are target language**.

## 15. Humor Should Be Situational

Humor is encouraged because memorable situations improve attention and recall. Beginner-level humor should usually come from mistaken identity · an animal behaving unexpectedly · an exaggerated but understandable object · repeated failed attempts · an unexpected possession · a character interpreting something literally · a visual contradiction.

Avoid humor dependent on sophisticated wordplay · culturally obscure references · humiliation · characters being portrayed as stupid.

## 16. The Story Must Respect Character Dignity

Characters may misunderstand, forget, choose incorrectly, fail, become confused. But they should not exist merely to be mocked. The learner should be able to identify with them. The emotional tone should generally remain warm · curious · playful · humane.

## 17. Information Must Be Controlled

Do not let characters know things without evidence. If Sara knows Omar has the book, establish how she knows: she sees it · Omar tells her · another character tells her · it was previously established.

Similarly, **illustrations must not reveal information the story is intentionally withholding.** Maintain *character knowledge → reader knowledge → visual knowledge* coherently.

## 18. Possession and Location Must Be Traceable

If an important object changes location or owner, the story must establish how. Avoid *book is in library → suddenly Omar has book* unless the change is shown or explained. This is especially important when practicing عنده · يعطي · يأخذ · يجد · يبحث · في · عند.

**CI repetition should never require broken logic.**

## 19. Natural Arabic Overrides Mechanical Target Counting

The story must sound like simple Arabic. Avoid relentless sequences such as *آدم يريد… آدم يذهب… آدم يرى… آدم يقول…* when normal Arabic discourse can use verb-first clauses · pronoun continuation · dialogue · natural subject omission · varied sentence rhythm.

Do not vary word order randomly. Vary it because discourse permits or requires it. **The quality standard is simple Arabic, not artificial Arabic.**

## 20. Do Not Distort Grammar to Protect the Level

If the story requires a completed past event, Story 2 may use an explicitly authorized past form. **Do not use present/imperfect Arabic as fake past narration.** **SC-073 item 2:** present and nonpast forms still appear in Story 2 wherever natural Arabic requires them — dialogue, direct thought, general truths, continuing states, descriptions that remain true — and **no clause is forced into a past verb** to satisfy the slot. **SC-073 item 3:** requiring past narration licenses **no paradigm**; a licensed form licenses only itself, and B-PA6's bar on drilled conjugation sequences is unaffected. Likewise, do not use a known structure unnaturally simply because the natural structure has not been taught. First try to redesign the situation. If a small support item remains necessary, establish it transparently.

## 21. Support Vocabulary Rule

For each story, distinguish **Core** (language learners are expected to acquire and recycle) · **Recycled** (established in previous units) · **Support** (a small amount needed to make the story natural) · **Recognition only** (learners need only understand in context).

Support vocabulary should be transparent · visually supportable · contextually obvious · infrequent · nonessential to later productive assessment unless deliberately promoted. **Do not allow support language to become a hidden second vocabulary list.**

## 22. Story 1 and Story 2 Must Differ Meaningfully

The two stories may share vocabulary · structures · thematic world · one recurring character · one object · one place. But they should differ in multiple narrative dimensions.

> **SC-079 (2026-09-15).** **رَزَان is the principal recurrent protagonist**: she centres at least one of the two stories in every unit from Unit 2. She need not appear in both. **A protagonist difference counts under this rule only when it changes the character's role, goal, knowledge, relationships, choices or experience of the problem** — a different name is not a difference. Characters are included only where they do necessary narrative or communicative work.

**Aim for difference in at least three of:** protagonist · problem · story engine · setting · object · information structure · emotional tone · ending · perspective · type of interaction.

> **GOVERNED BY SC-074 (2026-09-15), which corrects SC-073 item 6.** The **fixed present/past contrast does not count toward these three.** The temporal contrast is an **invariant structural distinction**, not one of the three selected differentiation dimensions. Each unit's stories must therefore differ **in temporal frame AND in at least three additional substantive dimensions from the list above**. Two guards: **superficial substitution — changing only names, objects, quantities or locations — does not satisfy the requirement**, and **required lexical redistribution does not automatically count as a narrative difference.**

Possible relationships: **Parallel** (different characters, different problems, same language) · **Sequel** (later, new problem) · **Backstory** (explains an earlier event) · **Different perspective** (follows a character who was secondary) · **Thematic echo** (same theme, unrelated plots) · **Consequence** (begins from Story 1 but develops independently).

**Do not simply translate Story 1 into past tense.**

## 23. Oral TPRS Comes Before or Around the Written Story

The written story should not carry the entire acquisition burden. Before reading, teachers should establish language through gestures · images · objects · personalized questions · student choices · mini-situations · circling · prediction.

Students should encounter much of the language orally before seeing the full text. A general sequence: **establish meaning → personalize → ask/create situation → oral story → comprehension checks → written story → retell/transfer.**

## 24. The Written Story Should Still Add Something

The reading should not simply transcribe the oral lesson. It may add one new detail · a more coherent narrative · a quiet reveal · richer dialogue · a visual payoff · a different ending · a small extension. **Learners should have a reason to read even if they understood the oral work.**

## 25. Story Length Should Grow Gradually

Do not force every unit to have equal-length stories. Early units may be very short. As cumulative language grows, stories can become longer without dramatically increasing new vocabulary. Growth should come mainly from **recycling more owned language in richer combinations** rather than continually adding new words.

## 26. Required Story 1 Design Card

*Before drafting Story 1, record:*

Unit · Current core structures · Recycled structures · Core nouns · Allowed support · Primary protagonist · Want/problem/question · Narrative engine · Anchor · Reason anchor matters · Main repetition mechanism · Dialogue need · First-person forms expected · Second-person forms expected · Information withheld · Turning point · Resolution · Possible final resonance · **Why this is still interesting if every word is understood.**

**Plus the vocabulary fields added by SC-058** (Vocabulary Recycling Architecture): New core vocabulary · Recent recycled vocabulary · Older recycled vocabulary · Support vocabulary · Words deliberately returning after a delay · How current vocabulary is used differently from previous appearances · Planned later recycling.

**Only then draft.**

## 27. Required Story 2 Design Card

*Before drafting Story 2, record:*

Unit · Relationship to Story 1 · New story engine · Core structures recycled · **Past forms authorized** *(SC-073: each must be verified against the Grammar Ledger with subsection and printed page at Gate A)* · **Past forms NOT authorized** · Recycled vocabulary · Allowed support · Primary protagonist · Want/problem/question · Anchor · Dialogue situation · First-person forms expected · Second-person forms expected · Main complication · Information structure · Turning point · Resolution · Final resonance · **Three ways this story differs from Story 1** *(SC-074: the tense contrast is invariant and does **not** count; name **three** substantive differences from rule 22's list)* · **Why this is not merely a tense-conversion exercise.**

**Plus the vocabulary fields added by SC-058:** Story 1 vocabulary intentionally recycled · Older vocabulary intentionally recycled · New vocabulary, if any · **Why any new lexical item is necessary** · Vocabulary now encountered in past-time narration · Vocabulary recycled through first-/second-person dialogue · Planned delayed return.

## 28. Quality Gate for Every Story

*Before approving either reading, answer:*

**Comprehension** — Can a novice follow the basic story? Is new language tightly controlled? Does core language dominate?

**CI/TPRS** — Are target structures repeated substantially? Is repetition meaningful? Can the story be circled and personalized? Does dialogue expose useful first/second-person forms?

**Narrative** — Does someone want, need, wonder, expect, or misunderstand something? Does something actually change? Is there a turning point? Is the ending earned?

**Logic** — Does every action have a plausible reason? Is possession traceable? Is character knowledge grounded? Are failed attempts reasonable?

**Language** — Is the Arabic natural? Is tense used honestly? Is word order natural? Does dialogue sound like actual speech at this level?

**Engagement** — Is there curiosity, humor, surprise, connection, or anticipation? Does the anchor matter? Would a learner have a reason to continue?

**Restraint** — Did the story avoid vocabulary explosion? Did support remain support? Did the story avoid unnecessary explanation?

**If any major answer is no, revise before producing downstream activities.**

**Extended by SC-058** with the Vocabulary Recycling Architecture's eight further approval conditions — see that document's *Addition to the Final Quality Gate*. **Condition 8 (a recorded future return for important new vocabulary) cannot be answered without the Cumulative Recycling Map**, which is therefore a precondition of any unit's final approval.

## 29. The Governing Formula

The stories should share this deep architecture:

> **limited language + high comprehensibility + motivated repetition + human purpose + natural dialogue + something genuinely unresolved**

But they should not share the same surface plot. The course should feel **linguistically cumulative but narratively fresh**. The aim is not twenty versions of *"someone wants something, goes somewhere, and finds it."* The aim is **twenty different stories built from an increasingly familiar language system.**

## 30. Final Standard

A successful course reading should make two things happen simultaneously. The teacher should be able to say *"this gives me enormous amounts of comprehensible repetition."* The learner should feel *"I want to know what happens."* **When both are true, the story is doing its job.**

# Appendix — Editor's implementation notes (not part of the rules)

*Added under SC-057. Records how the blueprint lands on instruments that already exist, and what it changes.*

## A · What this supersedes

The **Story Design Standard** (SC-031 — the owner's 30 criteria plus the Editor's §A–§E wrapper) is now **subordinate to this blueprint**. Where the two overlap they agree; where they differ, the blueprint governs. The Standard is retained for the criteria the blueprint does not cover (vocalisation, the وَ audit, banned features, the em-dash rule, SC-027's romance guard, SC-036's same-gender rule), and its §E — the tense law and the absurdity licence — is **absorbed into blueprint rules 1, 7 and 15** rather than kept separately.

## B · What is genuinely new, and must now be tracked at course level

1. **Engine rotation (rule 4).** No engine may repeat in consecutive units. This is the first rule in the line that constrains a unit by reference to the unit before it, so it needs a **register of engines used per unit**, kept in the working map. Unit 1 is entered below.
2. **Shape variation (rule 5).** Same, with the eight named shapes.
3. **The design cards (rules 26–27).** A process gate: no reading is drafted before its card is recorded. This converts story design from something argued after the fact into something declared before.
4. **The quality gate (rule 28).** Seven headings, answered per reading, before downstream activities are built. This replaces the Editor's ad-hoc generation-prompt checklist as the approval instrument.
5. **Person-form coverage (rules 8–10)** becomes measurable: a reading is checked for what its dialogue actually supplies in first and second person, not merely for whether dialogue exists.

## C · ~~One structural conflict the owner must resolve~~ — **CLOSED (SC-062)**

**Rule 23 assumes a teacher-delivered oral phase. The course has no teacher book (SC-045), and no facilitation notes beyond the one-line rubrics printed on the pages (SC-049).**

The blueprint's sequence — *establish meaning → personalize → ask/create situation → oral story → comprehension checks → written story → retell/transfer* — describes circling, personalized questions and student choices, none of which a learner can run alone and none of which the products currently script. Rule 24 then depends on rule 23 having happened: the written story "should still add something" **to an oral lesson that nothing in the course provides.**

Three ways out, for the owner:

**(i)** The oral phase is **classroom practice, not product** — the blueprint states the pedagogy the course assumes a teacher already knows, and rules 23–24 bind the *author's* design (leave room for it) rather than the *product's* contents. Cheapest, and consistent with SC-045.

**(ii)** The oral phase becomes a **minimal scripted page per unit** — not a teacher book, a single printed sheet of the circling questions for that story. This contradicts SC-045 least if it is framed as one more printed page, like the C-format rubrics.

**(iii)** SC-045 is reopened.

**RULED (SC-062): option (i).** The oral phase is **classroom practice, not product.** The blueprint's sequence describes what a teacher does; rules 23 and 24 bind the **author's design** — leave room for the oral phase, and make the written story add something to it — rather than obliging the course to print a script for it. **SC-045 stands: no teacher book.** §22's input-first sequence reads the same way: it is a description of teaching, not a specification of pages. The conflict opened here is closed at its cheapest point.
